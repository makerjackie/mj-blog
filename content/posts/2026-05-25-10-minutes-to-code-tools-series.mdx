我很早之前写过一篇 [十分钟 SpaceVim 入门](https://github.com/makerjackie/10-minutes-to-SpaceVim/blob/master/README-zh.md)。

那篇文章现在回头看，写法很朴素，但我还挺喜欢它。

因为它没有把读者当成要被「教育」的人，而是直接说，我带你试一下，不喜欢可以退回去，原来的东西不会被删掉。

这就是我想重新做这个系列的原因。

现在工具变得太多了，编辑器有 Helix、Zed，AI 编程助手有 Codex、Claude Code。每一个工具单独看都很强，但对新手来说，真正卡住的通常不是高级能力，而是最开始那几分钟：

我怎么安装？

我怎么打开一个项目？

我按什么键？

我怎么退出？

我怎么知道它真的能帮我？

所以这个系列只解决一个问题，10 分钟内让你赢一次。

## 这个系列会怎么写

每篇文章都尽量保持同一个结构：

1. 安装，先让工具跑起来。
2. 基本概念，只讲刚开始必须知道的那几个。
3. 第一次尝试，打开一个真实项目或者文件。
4. 常用入口，把最常用的快捷键、命令、提示方式列出来。
5. 什么时候继续深入，什么时候先别折腾。

不追求把所有配置都讲完。

说实话，很多工具的官方文档已经很全了。我们真正需要的是一个更轻的入口，一个让你能马上开始动手的入口。

## 为什么先选这几个

Helix 是一个很适合重新理解编辑器的工具。

它不是 Vim 的又一个配置包，而是一个默认体验比较完整的终端编辑器。你不需要先搭插件系统，就能用文件选择、项目搜索、多选区和主题。

Zed 更像现代编辑器的另一条路线。

它有很快的界面、很顺的项目导航，也把 AI、协作、终端这些东西放进了编辑器内部。对很多不想折腾 Vim 配置的人来说，Zed 可能是更容易上手的选择。

Codex 和 Claude Code 则是另一类东西。

它们不是编辑器，而是能读代码、改代码、跑命令的编程代理。你给它一个任务，它可以自己看项目、提出计划、改文件、跑测试，再把结果交给你确认。

这类工具最重要的不是记命令。

而是学会怎么把任务讲清楚，怎么给它边界，怎么检查它改了什么。

## 我希望它变成什么

我希望这个系列不是一堆工具推荐，而是一组很轻的上手入口。

你今天想试 Helix，就打开 Helix 那篇。

你今天想试 Zed，就打开 Zed 那篇。

你今天想试 AI 编程助手，就先从 Codex 或 Claude Code 里挑一个，不用同时学四个。

不用着急变成高手。

先把工具跑起来，先完成一次真实的小任务，再说。
