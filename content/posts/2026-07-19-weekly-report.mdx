# 这一周：OneSay 进入发布阶段，01MVP 商业化开始成形

这是我的第一篇公开个人周报。

以前做周报，我很容易把它写成一串提交记录：修了什么、发布了什么、又新开了什么项目。但回头看，这些信息并不能回答更重要的问题：我这一周到底在推进什么？哪些事情值得继续？哪些作品其实已经失败了？

所以这次，我想把工作和作品放在同一张图里看。

## 本周总览

这一周的主要精力集中在三条长期主线上：

- **OneSay**：从本地开发、账户数据隔离、移动端体验，一路推进到原生计费、API 契约和 TestFlight 发布准备。
- **01MVP**：重新整理会员定位、付费内容、推荐机制，并继续推进 Cloudflare D1 和数字产品授权。
- **One Apps**：同时推进 OneFocus、OneVoice、OneMarkup、OnePosture 等多个正式 App 的体验与发布工作。

除此之外，我也完成了 HackathonWeekly 的存储与退款流程改造、Tiny Planets 的一轮迭代，以及 MakerJackie 作品集页面的重新整理。

## OneSay：从功能开发走向完整发布

OneSay 是这周投入最多的项目。

我先处理了一个不太显眼、但很重要的问题：不同账号切换时，本地 workspace 有混用数据的风险。现在每个账号都有独立的本地工作区，并增加了旧数据迁移和回归验证。

开发环境也重新明确为一套完整链路：API、数据库、已经安装的 OneSay Dev App，以及负责快捷键捕获的 watcher。过去那种只启动 Flutter 界面、却忘记本地 API 或 watcher 的情况，终于有了统一约定。

产品层面，这周继续调整了移动端录音、笔记详情、跨平台工作台和 AI Coach。发布层面则完成了 iOS 隐私用途说明修复，替换后的构建已经通过处理，可以进入内部 TestFlight 测试。

同时，我决定逐步用 Apple 和 Google 的原生计费替换 RevenueCat，并把桌面端与移动端的数据接口收敛到稳定的 REST / OpenAPI 契约。

它还没有完全结束，但已经从「一个功能很多的应用」开始变成「一个可以持续开发、测试和发布的产品」。

## 01MVP：商业模式开始变得更清楚

这周把会员统一命名为 **01MVP 实战会员**，不再强调短期早鸟，而是强调长期的实战价值。

内容也重新划分了边界：公共参考资料继续免费，真正需要完整步骤、真实项目和高密度经验的内容进入会员区。ASC iOS 发布教程就是一个例子——基础流程可以公开，但完整命令、发布细节和真实案例更适合放进实战内容。

推荐机制也做了调整。付费会员现在可以正常分享推荐链接，整个流程完成了验证。除此之外，我还加入了咨询服务入口，并开始搭建数字产品的购买、授权和激活链路。

基础设施方面，01MVP 的数据库逐步迁移到 Cloudflare D1。这个方向已经进入实际实现，但完整的生产数据核对、监控与回滚仍然需要继续完成。

## One Apps：开始像一个产品矩阵

One Apps 这一周的变化非常密集：

- OneFocus 持续调整跨设备专注流程、声音、历史记录和 App Store 审核问题。
- OneVoice 完成迁移，并继续改进录音库、播放和搜索。
- OneMarkup 增加离线文档查看、可编辑预览、自动保存和分享。
- OnePosture 更新了购买指南与下载入口。

最大的感受是：当 App 数量增加以后，真正缺的已经不只是开发速度，而是一套共享的发布系统——版本、截图、商店文案、审核状态、网站下载链接，都应该有统一的验收清单。

这会是下一阶段 One Apps 最需要补的能力。

## 两个作品带来的相反结论

这周我也重新看了两个独立作品。

### shapeof.world：我喜欢的作品

shapeof.world 对我来说是比较成功的。

它不一定是用户最多、商业价值最高的项目，但我喜欢最终呈现出来的效果。它更像一个互动叙事与艺术作品，而不是一个等待增长指标的产品。

这种「我真的喜欢它」的判断，本身就足以让它进入我的代表作品。

### Tiny Planets：我决定承认它失败了

Tiny Planets 的问题也很明确：我一直没有做出真正好玩的场景模式。

我尝试过增加叙事、探索、观测站记忆和星球场景，也做过多轮发布和验证，但核心体验始终没有达到预期。继续增加内容并不能解决“不够好玩”这个根本问题。

所以我基本决定停止维护它。

这并不意味着要删除它。它更适合留在 Experiments：作为一次真实但失败的独立游戏实验，提醒我以后先验证核心乐趣，再扩充世界观和内容。

## 我重新整理了 MakerJackie 的作品结构

以后我的项目会分成四类：

### 01MVP

教程、课程、模板、陪跑和开发案例。它解决的是「如何用 AI 把产品真正做出来」。

### One Apps

小而美、长期维护、面向普通用户的正式 App。这里的项目需要持续更新，也需要承担发布和用户体验责任。

### Independent Works

shapeof.world、独立游戏、互动网站、叙事与艺术作品。它们不一定追求商业规模，但应该表达一些属于我的东西。

### Experiments

原型、周末作品、无用 App 和技术实验。这里允许失败，也允许停止维护。Tiny Planets 现在属于这里。

我希望这个分类能让我以后更诚实地判断一个项目：它是产品、作品，还是实验？它需要长期维护，还是已经完成了自己的使命？

## 其他交付

这周还完成了一些相对独立的工作：

- HackathonWeekly 的对象资源迁移到 Cloudflare R2，并把已付款报名的取消流程改成退款申请、组织者审批和并发保护。
- MakerJackie 项目页面重新区分长期主线、独立作品与实验。
- 整理了 UU Remote 视频的多平台发布文案、封面和关键帧素材。
- 清理了一些已经没有必要保留的开发技能和工具流程。

## 下周想完成什么

下周最重要的不是再开更多项目，而是把发布和验收做完整：

1. 逐一确认 OneSay、OneFocus、OneVoice、OneMarkup 等 App 的 TestFlight / App Store 状态。
2. 完成 D1 和 R2 的生产数据、域名健康、监控与回滚检查。
3. 为 One Apps 固化一套跨产品发布清单。
4. 验证 01MVP 数字产品从购买、邮件、激活到后台管理的完整链路。
5. 把已经做好的 UU Remote 素材真正发布出去，并记录反馈。

这一周做了很多事情，但最值得记录的也许不是某个功能，而是我开始接受：长期产品、个人作品和实验，本来就应该用不同的标准评价。
